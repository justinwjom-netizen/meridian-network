Getting started

Meridian runs as a monorepo. The backend serves the API, WebSocket feed and this site; the terminal and marketing pages read demo data with a clean integration boundary.

terminal
npm install
npm run start:server   # http://localhost:3001
npm run mcp:pay        # meridian-pay-mcp (stdio)
npm run mcp:trade      # meridian-trade-mcp (stdio)

Architecture

A user-owned Strategist executes strategies through HSKSwap. When it needs intelligence, it purchases services from specialist agents via HSP Payment Mandates, settled on HSK Chain. User-defined policies constrain trades, spend, payees and daily losses. See How it works.

Payment workflow

A merchant agent returns signed conditions; the Strategist builds a mandate within policy; it settles on HSK Chain; the receipt is verified before the service result is released.

meridian-pay-mcp
create_payment_conditions(payee, token, amount, service)
build_mandate(conditions)        // nonce + expiry
submit_mandate(mandate)           // settle on HSK Chain
verify_settlement(orderId)
list_payments()

Trading workflow

meridian-trade-mcp
set_policy(perTradeCap, dailyLoss, agentBudget, slippage)
get_quote(pair)
propose_trade(pair, size)         // validated vs PolicyVault
get_positions() / get_pnl()
list_agents()

Security model

Bounded session keys, per-trade and daily caps, approved-payee allowlists, replay-protected mandates and high-water-mark escrow. Full detail on the Security page.

Error handling

Live mode surfaces rejected signatures, failed RPC, stale data, contract reverts and unavailable services. Simulated success is never substituted for a failed live transaction.

These docs describe intended interfaces — validate against the implementation before wiring live calls.
